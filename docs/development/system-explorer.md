# Monitoring workspace

The `feature/system-explorer` branch makes the monitoring workspace the signed-in application home at `/`. Login, the application wordmark, and the Monitoring navigation item lead here. Existing `/explorer`, `/spatial-lab`, and `/services` links redirect to `/` and require the same authentication. Both development and compiled production builds include this lazy-loaded home independently of the old spatial experiment flag.

Every application page uses the same sticky header, theme control, and application menu. The menu provides Monitoring, Entities, Sources, Anomalies, Account, Settings, and Logout. Logout clears the session and returns to login immediately. `/entities` is a searchable, virtualized directory from the generic `/v1/system` catalogue; entity links open their definition in the monitoring workspace. Old `/stations` and `/favourites` bookmarks redirect to `/entities`. Historical monitoring and recording workflows retain their existing APIs and topic-format constraints.

## Navigation

Enter a broker, entity, or topic branch to replace the current list. Back restores its scroll position and visible keyboard focus. The current heading opens an ancestor menu. Single-child MQTT paths fold into one row while preserving every original topic segment and the complete ancestry. Topics with both their own readings and subtopics show both. Several payload fields on one MQTT topic are separate reading leaves.

Search reaches closed branches by name, MQTT path, payload field, or ancestor context. Cmd/Ctrl+K opens and focuses search even with the sidebar closed; ArrowDown enters results. Up/Down and Home/End move within lists; Right opens and Left goes back. Selecting a reading reveals its canonical parent and opens its inspector. Browsing other branches leaves that preview in place. The default main view is the service list. Entering a catalogue branch filters it to monitors using that branch’s exact accepted inputs. Returning to Monitoring shows all services without resetting the sidebar position. Browsing while inspecting a reading or service preserves that inspection.

The mobile sidebar uses an accessible modal drawer, with focus containment, Escape/backdrop dismissal, and focus returned to its opening control. Reduced-motion preferences disable navigation transitions. Light and dark themes follow the existing application theme.

The desktop sidebar has a draggable right edge. Width ranges from 240 to 480 pixels, with at least 480 pixels left for the workspace; narrower desktop windows temporarily constrain the displayed width without replacing the saved preference. Double-click resets to 288 pixels. The focused separator supports Left/Right (16 pixels), Shift+Left/Right (64 pixels), and Home/End. Escape or a cancelled pointer restores the width before the drag. Width persists per account in this browser. Dragging updates one CSS layout variable per animation frame and commits preferences only when released. Mobile continues to use its fixed-width drawer.

## Monitoring services

The home lists actual services from `/v1/monitors/all?active_only=false`: saved name, monitored scope, detector, lifecycle stage, preparation progress, last reported update and processed inputs. It has search and state filters, with Attention shown when a service reports a failure, degradation or stale status. No anomaly-count dashboard or fabricated healthy state is shown. Empty deployments offer service creation without activating any collection automatically.

The overview uses one compact status request every 20 seconds while visible, refreshing every five seconds while a service is open, without per-service Docker probes or history subscriptions. List rows are virtualized. Explicit service inspection loads its settings; Evidence mounts only the selected reading’s chart. Preparation, read-only configuration, existing static/adaptive detector settings, dynamic score/threshold charts, and stop/remove actions retain the real backend lifecycle. Unsupported pause/resume and notification-delivery controls are not presented.

`/?service=<stable-service-id>` restores a selected monitor; `tab` and `stream` select its detail tab and evidence input. Service names save quietly on Enter or blur through an administrator-only `/v1/monitors/<id>/label` PATCH and persist in the database’s launch metadata. Workload names, IDs and subscriptions remain stable. Restart capture preserves names for legacy services too. Detail settings exclude connection credentials.

Create service chooses a broker/entity, reviews an explicit Off/Sample/Original collection policy, then configures a static or adaptive detector using the acknowledged numeric input bindings. Starting remains disabled until collection is applied. A reading’s Configure monitoring link uses `/?create=monitoring&reading=<stable-reading-id>`; its input is preselected. Active ownership prevents a second service from claiming a reading. A successful launch opens the returned service ID.

Stars save service and reading favourites per account **in this browser**, alongside sidebar width and navigation. Favourites appear as direct shortcuts in the sidebar; display-name edits do not break them. They do not alter catalogue structure or collection policy and are not included in catalogue export. Stored unresolved references are retained during temporary failures or loading. Personal grouping remains inactive.

Notification recipients remain deployment-managed. The existing anomaly email endpoint is preserved; this first version does not claim per-service subscriptions or a record of delivered alerts.

## Catalogue

Catalogue names and structural changes use the existing revisioned `/v1/system` database API and permission checks. Enter or leaving an inline name field saves; Escape cancels. A rejected or conflicting save is never presented as successful.

Catalogue groups remain part of the saved system definition and are available from the sidebar when present. Personal grouping is currently removed from the interface: no membership editor, personal scopes, color overlays, or workspace export. Existing per-account personal group data remains in browser storage for later use. A previously selected personal scope falls back to the catalogue without deleting its saved groups. Ordinary navigation and sidebar visibility still persist per account.

Settings export the latest acknowledged database catalogue. Imports accept generic system documents, the legacy broker catalogue, and the system definition contained in previous spatial or explorer workspace exports. Inactive personal preferences from those files do not replace browser data. Counts and scope are reviewed before explicit replacement at the captured database revision. Importing never starts a live connection.

## Performance and telemetry

TanStack Virtual renders the visible list and a small overscan buffer, including variable-height names. The navigation index and labels are built only when configuration changes. Live updates do not rebuild or reorder the catalogue. Search uses precomputed strings and limits its result list to 100 entries; refine the query for more specific matches. Service creation, service details, preview, chart code, settings, and the structure editor load separately. The explorer has no WebGL or Three.js dependency.

The existing schema limits still apply: 128 brokers, 2,048 entities, 4,096 readings, and a 1 MiB system definition. UI tests exercise 4,000 sibling topics and deeply nested MQTT paths. Supporting much larger catalogues will require server-side paging and indexed search in addition to the virtualized UI.

Live telemetry uses the existing backend MQTT session API. **Connect**, **Disconnect**, and **Retry** control the current view in every deployment. Connection states use the same labels for all data sources; generated feeds are identified separately as **Simulated data**. Values and limited history stay in memory; existing collection policies and monitoring services remain independent. Private brokers still require reachable networking and configured credential references. An imported catalogue alone does not provide that access. The isolated local deployment can run catalogue-shaped MQTT fixtures without changing the connection controls. Disconnected, waiting, and failed connections are shown honestly.

Reading charts reuse the details page's ECharts model, detector selection, threshold history, and event details. The time selector limits the history window relative to the latest available observation, so a quiet or stopped reading still opens with its last recorded data. The plot fits actual samples, with a visible marker for a single sample. Ctrl+scroll zooms, dragging pans, and the overview selects a range. Keyboard controls support +/−, Left/Right, and Home. Inspection holds absolute timestamps while new samples arrive; Full range returns to automatic fitting. Display-name edits preserve inspection; changing the input resets it.

Recorded numeric readings open without Connect: collection runs independently of the page, and their status reflects the persistent ingress rather than the temporary preview. Stored samples load independently of monitoring metadata, then poll with ingestion cursors every two seconds while the reading is visible. The latest numeric value uses the same history, showing the actual observation date and time even when no preview connection exists. A workspace-owned cache keeps up to 12 visited inputs and 32,768 combined telemetry/evidence observations. Returning displays cached data immediately while refreshing; after a longer absence it requests the latest bounded page rather than replaying an unlimited backlog. The cache is isolated by account, input definition and accepted identity, is discarded when the workspace closes, and does not subscribe to hidden readings. A fresh login loads history from the database. Boolean and text collection retain the existing latest-state persistence semantics.

The inspector's Collection controls explicitly select Off, Sample (1–3,600 seconds), or Original rate. Actions review their scope and any affected monitors before applying. Broker, entity, topic and catalogue-group scopes operate on their current reading IDs; new readings remain Off. Sources opens the same generic catalogue editor. Importing metadata does not activate a policy contained in a file: existing selections survive by stable reading ID and new entries remain unselected.

## Upgrade and deployment

Migration `004_system_catalogue.sql` adds the saved-system and generic collection tables through the existing transactional release workflow. It also supports main installations whose original tables predate the migration ledger. Existing accounts, collection selections, telemetry, evidence, and saved monitor launches remain in place. Reading the new workspace adapts the main catalogue without activating the generic collector or rewriting the legacy configuration. Renames retain main's existing collection route. An explicit collection change or a structural change to admitted inputs establishes the generic runtime, retaining unambiguous historical input identities and reconciling removed inputs. Running monitors remain protected before that handover. Removing and reimporting inputs restores their history bindings; newly added inputs still require explicit collection opt-in.

Production readiness checks the active collection runtime and its matching ingress/collector revision, including idle catalogues with all inputs Off. The generic ingress controller uses an independent advisory lock so it cannot block account administration or schema migrations. Preview and persistent collection share the existing operator access configuration; production VPN registration, credential references, and network reachability still determine access to private sources.

The deployment smoke workflow exercises the main-format MQTT and monitoring journeys before the generic workspace. It then checks real generic upstream MQTT ingestion, adaptive score/threshold evidence, and database backup/restore followed by repeated deployment. The deployment rehearsal retains catalogue revisions, historical bindings, recorded values, membership, monitor names, and a single resumed worker. Synthetic brokers and disposable credentials belong only to that rehearsal.

The first explicit collection action creates `system_collection_configuration` and transfers admission from the legacy adapter to the generic runtime. Existing historical bindings are retained when their inputs match unambiguously. Other readings get stable internal entity and reading identities in the `telemetry/<entity>/<reading>` namespace. JSON Pointer bindings support multiple fields on one upstream topic. The proxy, history APIs, monitor provisioning and RADAR topic parsing accept both namespaces. The legacy catalogue remains available for compatibility/export; its operational writes are rejected while the generic runtime owns collection.

Persistent selected subscriptions run in TACTIC independently of browser leases, forward raw envelopes through internal EMQX, and feed the existing bounded collector. Only admitted fresh numeric observations enter telemetry history and the accepted detector feed; boolean/text/identifier observations keep the existing latest-state persistence behavior. Retained snapshots establish state but do not become fresh detector input. Configuration generations prevent queued observations from an earlier mapping entering a new mapping. Explicit Off removes subscriptions and stops admission; existing numeric history is preserved. Active monitors must be paused before their inputs or collection cadence change.

Temporary Connect leases subscribe only to readings that need a preview in the focused scope and use the union of active viewers' selections. Recorded numeric readings use database history instead of a duplicate preview subscription. Browsing metadata without a focused selection opens no upstream subscriptions. Changing topics on a healthy broker updates subscriptions on the existing MQTT connection; leaving a broker releases its worker. Previously observed preview samples remain in the same fixed global buffer across scope resets and hidden-tab pauses, with timestamp deduplication when snapshots replay. Disconnect, account/input-definition changes and buffer limits still clear or expire temporary data. This path never activates collection or invents values for unobserved intervals. Collection status and latest recorded values poll a compact scoped API; stored history and monitoring evidence poll only for the selected reading. Scores and dynamic thresholds retain the details chart's behavior. The Configure monitoring link opens integrated service creation with the selected reading preselected and catalogue names displayed.

Operator broker allowlists, credential references and network access remain required. `SYSTEM_COLLECTION_ENABLED` controls persistent ingestion independently of `SYSTEM_LIVE_ENABLED`. The internal EMQX publisher uses the configured broker/TLS defaults and `SYSTEM_COLLECTION_MQTT_USERNAME`, `SYSTEM_COLLECTION_MQTT_API_KEY`, and `SYSTEM_COLLECTION_MQTT_CA_FILE`. Production mounts the existing proxy credential and CA as private TACTIC secrets; catalogue exports never contain them.

For an existing isolated local deployment, rebuild the frontend, API gateway, TACTIC, MQTT proxy, RADAR image and DB sync using the configured `dev/local` Compose project. Run DB sync to add the configuration table, then recreate the application services. Preserve database volumes, existing monitor workloads and private configuration. Do not reapply the synthetic fixture when testing a saved private catalogue. See [local deployment](local-deployment.md) for initial setup.

## Shared interface

`App.css` owns semantic colors, typography, spacing and component states. `AppHeader` and `ApplicationMenu` provide identical navigation on the workspace and functional pages; `PageShell` sets their content width and spacing. The explorer uses those tokens rather than a separate palette. Auth, forms, tables, menus, dialogs and empty/error/loading states use the same restrained surfaces. Quiet branding details remain part of the interface: authentication screens use the original repeating slash monogram behind the form, without animation or interaction layers over controls. Mobile controls have 44-pixel targets, including popover actions inside the explorer drawer. Broker and entity definitions display their actual catalogue metadata; user-provided labels and MQTT paths remain verbatim.
